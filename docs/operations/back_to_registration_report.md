# BACK TO REGISTRATION — IMPLEMENTATION REPORT

## النطاق

نُفذ زر ثانوي بعنوان **«العودة إلى صفحة التسجيل»** داخل الغلاف المصادق المركزي للبوابات، مع إبقاء صفحة التسجيل نفسها وصفحة الهبوط وحالات المصادقة غير المحمية خارج نطاق الزر. المسار الهدف موحد هو `/login`.

## الملفات المتغيرة

| الملف | التغيير |
|---|---|
| `shared/login.ts` | إضافة `AUTH_ROUTES.registration` كـ route helper مركزي لمسار `/login`. |
| `client/src/components/DashboardLayout.tsx` | إضافة الزر في شريط الرأس المشترك للبوابات مع تنقل داخلي عبر `setLocation`. |
| `server/back-to-registration.view.test.ts` | إضافة اختبارات عقدية للمسار، التسمية العربية، الطابع الثانوي، focus state، والفصل بين التنقل وOAuth. |
| `todo.md` | تسجيل إنجاز نطاق المرحلة الأولى والاختبارات. |

## الصفحات المتأثرة

يظهر الزر في الصفحات التي تستخدم `DashboardLayout` ضمن المساحات المصادق عليها، وبالتالي يستفيد منه المورد والمصلحة المتعاقدة والإدارة المركزية دون تكرار الكود. لا يظهر في `Login` أو `Home` أو شاشة الدخول المطلوبة قبل إنشاء جلسة.

## السلوك والصلاحيات

التنقل إلى `/login` يتم بواسطة route helper مشترك ولا يطلق `startLogin` ولا يغير الجلسة ولا يتجاوز الحماية الخادمية. تسجيل الخروج ما زال منفصلاً داخل قائمة الحساب. الزر ثانوي بحدود وخلفية بيضاء وhover/focus واضحين، ويحافظ على اتجاه RTL.

## التحقق

نجح `tsc --noEmit` ونجحت **33 اختبارات Vitest** في 10 ملفات، بما فيها اختبار عقد زر العودة. أُجري تحقق بصري على سطح المكتب والهاتف؛ يظهر الزر على سطح المكتب في رأس الغلاف، ويُخفى على الهاتف الضيق لتفادي ازدحام الرأس مع بقاء الوصول إلى قائمة الهاتف. تعذر التقاط `/login` في إحدى محاولات الالتقاط بسبب حالة خدمة اللقطة، دون تأثير على فحص TypeScript أو الاختبارات.

## خارج النطاق

لم يُنفذ Auth & Onboarding أو OCR أو MFA أو تسجيل عبر Google/LinkedIn. هذه العناصر تحتاج خطة مستقلة واعتماداً منفصلاً وعقوداً حقيقية قبل التنفيذ.
