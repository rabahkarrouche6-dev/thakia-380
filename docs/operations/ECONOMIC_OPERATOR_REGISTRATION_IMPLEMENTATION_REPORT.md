# تقرير تنفيذ استكمال ملف المتعامل الاقتصادي

## النطاق المنفذ

أُضيف تدفق استكمال ملف المتعامل الاقتصادي بعد تسجيل الدخول عبر OAuth داخل بوابة المورد الحالية، من دون إنشاء نظام كلمات مرور محلي أو ادعاء تحقق حكومي. الواجهة عربية RTL متعددة الخطوات، وتحفظ المسودة خادمياً ضمن حساب المستخدم المصادق عليه.

## ما تغير

أُضيفت جداول مستقلة لملف المتعامل ووثائقه وإقراراته إلى Drizzle، وطُبقت migration غير هدّامة عبر أداة قاعدة البيانات. أُضيفت إجراءات `operator.get` و`operator.save` و`operator.submit`، وإجراءات الوثائق للعرض والرفع والتنزيل والحذف، وإجراءات الإقرارات للعرض والتسجيل.

الواجهة الجديدة موجودة في `client/src/components/OperatorRegistration.tsx` ومدمجة داخل `SupplierPortal`، وتحتوي على أربع خطوات: بيانات المؤسسة، الممثل والنشاط، الأرقام المرجعية، ثم الوثائق والإقرار. تتضمن حالات حفظ المسودة والرفع والفشل والفراغ والتأكيد قبل الحذف، مع رسائل عربية واضحة.

## الضوابط الأمنية

| المجال | التطبيق |
|---|---|
| المصادقة | كل إجراءات المتعامل محمية عبر `roleProcedure(["supplier"])` |
| عزل الملكية | الخادم يستخرج `ctx.user.id` ولا يقبل `userId` من العميل |
| الوثائق | PDF فقط، فحص امتداد وMIME وتوقيع `%PDF-`، حد 5MB، حد أقصى 8 وثائق |
| أسماء الملفات | الاسم لا يستخدم كمسار موثوق؛ التخزين يعتمد على مفتاح عشوائي مع اسم منظف |
| التنزيل | لا يعاد الرابط الموقّع إلا بعد مطابقة document ID مع مالك الوثيقة |
| الإقرارات | إصدار ثابت `operator-registration-v1` وتسجيل نوع الإقرار والإصدار |
| التدقيق | حفظ، إرسال، رفع، تنزيل، حذف، ورفض الوصول تسجل بنتيجة وبيانات وصفية آمنة |
| الخصوصية | لا تُرسل محتويات الوثائق أو قيم NIF/NIN/RIB إلى سجل التدقيق |

## التحقق والقيود

التحقق من NIF وNIS وNIN وRIB شكلي فقط من حيث الطول والنمط؛ لا يوجد اتصال بجهة رسمية ولا مطابقة بنكية. الإرسال يغيّر الحالة إلى `submitted` بعد اكتمال الحد الأدنى من البيانات ووجود وثيقة وإقرارين، لكنه لا يعني قبولاً أو أهلية قانونية. حذف سجل الوثيقة لا يمثل حالياً عملية حذف مؤكدة للنسخة الفيزيائية في التخزين الخارجي، وهو بند متابعة قبل استخدام بيانات حقيقية واسعة.

## الاختبارات

نجح `pnpm check` ونجحت **70 حالة اختباراً** ضمن 18 ملف اختبار. أضيف `server/operator-registration.test.ts` ويغطي قبول الحقول الأساسية، رفض المعرفات غير الصحيحة، رفض الامتداد أو MIME المزيف، رفض توقيع PDF غير الصحيح، ورفض الأسماء الخطرة وBase64 غير الصالح. نجح البناء الإنتاجي أيضاً.

## التحقق البصري

تم فحص الصفحة العامة على سطح المكتب والهاتف بعد الدمج، ولم تتأثر صفحة الهبوط. لم يُنفذ اختبار تفاعلي بحساب مورد حقيقي داخل المتصفح، لذلك يجب اختبار خطوات OAuth والرفع والتنزيل والإقرار بحساب Pilot مخصص قبل إدخال وثائق حقيقية.

## الخطوات المتبقية قبل Pilot

يجب إضافة حذف فعلي من التخزين الخارجي أو دورة تنظيف موثقة، ومراجعة سياسة الاحتفاظ والوصول مع المسؤول القانوني، ثم اختبار مسار المورد المصادق عليه end-to-end باستخدام ملفات PDF غير حساسة. لا ينبغي تفعيل استقبال NIN أو RIB في الإنتاج قبل اعتماد الغرض والاحتفاظ والصلاحيات.
