# ONBOARDING MVP IMPLEMENTATION REPORT

## النطاق

تم تنفيذ onboarding سياقي مختصر داخل البوابات الثلاث الحالية في `/app`، دون popup أو walkthrough متعدد الخطوات، ودون إضافة نموذج قاعدة بيانات أو endpoint أو صلاحية جديدة. تعتمد كل خطوة على نتائج استعلامات tRPC الحقيقية وعلى أقسام ومسارات موجودة مسبقاً.

## النصوص العربية النهائية

| الدور | النص |
|---|---|
| المتعامل الاقتصادي | **ابدأ من هنا** — لديك مساحة مخصصة لاكتشاف الصفقات وإعداد عروضك ومتابعة حالتها من مكان واحد. |
| المصلحة المتعاقدة | **ابدأ بإدارة صفقتك** — أنشئ صفقة، راجع مسوداتها، ثم تابع النشر والعروض من المسار المحمي للجهة. |
| الإدارة المركزية | **ابدأ بالمراجعة الرقابية** — راجع المؤشرات والصفقات وسجل التدقيق كما هي مسجلة فعلياً في المنصة. |

## شروط الظهور والإكمال

تظهر البطاقة داخل قسم `home` للمورد والسلطة المتعاقدة، وفي أعلى بوابة الإدارة المركزية. لا يظهر أي تقدم محسوب من قيم وهمية. يُستنتج الإكمال من البيانات الحالية: اكتمال ملف المورد من `profile.get.completion`، وجود صفقات منشورة من `tenders.published`، وجود عروض من `bids.mine`، وجود صفقات الجهة من `tenders.mine`، ووجود نتائج رقابية من استعلامات `regulator.*`.

تُحفظ حالة إخفاء البطاقة في `localStorage` بالمفتاح `safaqat-onboarding-dismissed:{role}:{userId}`. هذا يمنع إعادة ظهورها في المتصفح نفسه للحساب والدور نفسه، لكنه ليس حالة خادمية عابرة للأجهزة. لم يتم تقديم التخزين المحلي للمستخدم كإثبات إكمال مؤسسي، ولم تُضف حالة قاعدة بيانات غير موجودة.

## الصلاحيات والمسارات

لم تتغير صلاحيات الخادم. أزرار onboarding تنقل إلى الأقسام الموجودة في `/app` أو إلى عناصر موجودة داخل صفحة الإدارة المركزية. الوصول إلى البيانات والعمليات الحساسة ما زال محكوماً بإجراءات tRPC الخادمية القائمة، ولا يعتمد onboarding على إخفاء الأزرار كحماية.

## حالات الواجهة والوصول

المكوّن يدعم نصاً واضحاً للخطوة التالية، حالات الإكمال، زر إخفاء قابل للوحة المفاتيح، `aria-label` للزر، `aria-live` للملخص، و`focus-visible` من مكوّنات Button الموجودة. التصميم يستخدم RTL، ويتكيف مع العرض الضيق عبر `flex-wrap` و`grid` responsive. تمت معاينة `/app` على سطح المكتب بحجم 1280×720 وعلى الهاتف بحجم 390×844.

## التحقق

| الفحص | النتيجة |
|---|---|
| TypeScript عبر `pnpm check` | ناجح |
| Vitest عبر `pnpm test -- --run` | ناجح، بما في ذلك `server/onboarding.view.test.ts`؛ العدد الفعلي محفوظ في مخرجات التشغيل الأخيرة. |
| Build عبر `pnpm build` | ناجح. ظهر تحذير حجم chunk قائم من حزمة الواجهة، وليس خطأ بناء. |
| RTL/Desktop | تمت المعاينة بنجاح، والبطاقة تظهر باتجاه RTL داخل بوابة السلطة المتعاقدة. |
| Mobile 390×844 | تمت المعاينة؛ البطاقة تلتف عمودياً وتبقى أزرار الإجراء قابلة للوصول. |
| Keyboard/accessibility | تحقق عقدي من وجود زر إخفاء موسوم وCTA buttons؛ يلزم اختبار تفاعلي يدوي إضافي داخل جلسة مستخدم لكل دور. |
| Lint | ما زال غير ناجح بسبب 88 ملفاً قائماً غير منسق في المشروع، من بينها ملفات قديمة وتقارير؛ لم تُنفذ إعادة تنسيق شاملة حتى لا يتسع النطاق. |

## ما لم يُنفذ

لم تُضف خانة `onboardingCompleted` أو migration أو مزامنة خادمية. لم تُضف تنبيهات، توصيات، تحقق مؤسسي جديد، وثائق جديدة، أو مسارات غير مثبتة. لم تُعرض “تنبيهات متاحة” للإدارة المركزية كقدرة منجزة، لأن العقد الحالي لا يثبت وجودها.

## القيود والمخاطر

التخزين المحلي مرتبط بالمتصفح والجهاز؛ لذلك ستظهر البطاقة مجدداً عند استخدام جهاز آخر أو مسح بيانات المتصفح. إذا أصبح الإكمال مطلباً مؤسسياً عابراً للأجهزة، يلزم تصميم server-side مستقل مع مراجعة صلاحيات وتدقيق قبل اعتماده. كما أن تحقق لوحة المفاتيح تم على مستوى العقود والمعاينة، وليس اختباراً آلياً شاملاً لقارئ الشاشة.

## الخلاصة

تم إغلاق نطاق Onboarding MVP المطلوب بأقل تغيير ممكن، مع إبقاء كل الإرشادات مرتبطة ببيانات ومسارات حقيقية. النسخة الجاهزة للحفظ تشمل التخزين المحلي الاختياري، البطاقات السياقية للأدوار الثلاثة، اختبارات العقد، وتوثيق الحدود التشغيلية بوضوح.
