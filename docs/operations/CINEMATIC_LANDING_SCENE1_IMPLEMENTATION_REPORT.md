# تقرير تنفيذ المشهد السينمائي الافتتاحي — المشهد الأول

## الملخص التنفيذي

أُضيف مشهد افتتاحي بصري خفيف إلى الصفحة العامة لمنصة **صفقات ذكية**. يشرح المشهد رحلة الثقة من بيانات المؤسسة إلى أثر قابل للمراجعة، من خلال مسار SVG رأسي وأربع بطاقات متدرجة الظهور. التنفيذ يحافظ على النبرة المؤسسية العربية RTL، ويعرض الذكاء الاصطناعي بصفته **أداة استشارية** لا بديلاً عن الصلاحيات أو القرار البشري.

> القرار التصميمي: استخدام SVG وCSS و`IntersectionObserver` بدلاً من GSAP أو WebGL أو أصول مرئية ثقيلة، لأن هذا المشهد لا يحتاج محركاً زمنياً أو اعتماداً إضافياً.

## ما تم تنفيذه

| العنصر | التنفيذ | النتيجة |
|---|---|---|
| المكوّن | `client/src/components/CinematicLandingScene.tsx` | مكوّن مستقل قابل لإعادة الاستخدام داخل الصفحة العامة |
| الإدراج | `client/src/pages/Home.tsx` | يظهر بعد الـ Hero وقبل رحلة المتعامل الحالية |
| المسار | SVG رأسي بعقد أربع | يوضح التسلسل دون حركة مستمرة أو مؤقتات متكررة |
| الكشف | `IntersectionObserver` | يبدأ الظهور عند دخول القسم إلى مجال الرؤية، مع fallback عند عدم توفر API |
| الحركة | انتقالات `opacity` و`transform` و`stroke-dashoffset` | حركة خفيفة قابلة للمقاطعة ومناسبة للأداء |
| تقليل الحركة | قاعدة `prefers-reduced-motion` | تظهر العناصر فوراً وتُلغى الانتقالات غير الضرورية |
| الاختبار | `server/landing-page.test.ts` | تحقق عقدي من الإدراج، الرسائل الآمنة، ومراعاة الحركة |

## مخطط المشاهد النهائي

| المحطة | الرسالة المعروضة | حدود الرسالة |
|---|---|---|
| 01 — البصمة | ملف قابل للمراجعة مبني على بيانات المؤسسة الفعلية | لا يوجد ادعاء بقراءة الملف خلال مدة محددة |
| 02 — الرادار | اكتشاف وترتيب الصفقات المنشورة ذات الصلة | لا توجد نسبة مطابقة أو وعد بفرصة حصرية |
| 03 — المساعد | مراجعة استشارية لاكتمال العرض قبل الإرسال | لا قبول تلقائي ولا وعد بالأهلية أو الفوز |
| 04 — التتويج | أثر واضح عبر مسارات المنصة الفعلية | لا يظهر فوز افتراضي ولا تشفير أو Blockchain غير منفذ |

## قرار الهوية البصرية

يستخدم المشهد درجات الأزرق البحري والأخضر المؤسسي مع خلفية ورقية هادئة وحدود دقيقة. البنية غير زجاجية بشكل مفرط، ولا تعتمد على توهج مستمر؛ الهدف هو الإيحاء بمسار قرار موثق، لا لوحة SaaS عامة. على سطح المكتب يظهر العمود البصري إلى جانب البطاقات، بينما تتحول البنية إلى عمود واحد على الهاتف دون فقدان المحتوى.

## الوصول والاستجابة

المحتوى النصي موجود في DOM ويظل متاحاً دون نجاح JavaScript. القسم يحمل عنواناً مرتبطاً عبر `aria-labelledby`، والعناصر البصرية المساعدة موسومة `aria-hidden` أو `role="presentation"` عند الحاجة. البطاقات لا تعتمد على hover لإظهار معلومات أساسية، ويمكن الوصول إلى بقية الصفحة عبر لوحة المفاتيح. تم التحقق بصرياً على قياسي **390×844** و**1280×720** مع RTL.

## التحقق البرمجي

تم تشغيل `pnpm check` و`pnpm test` و`pnpm build` بعد التعديل. نجح فحص TypeScript والاختبارات والبناء. كما أُضيف اختبار عقدي خاص بالمشهد داخل `server/landing-page.test.ts` للتحقق من وجود المكوّن في الصفحة، الرسائل الاستشارية الآمنة، واستخدام `IntersectionObserver` و`prefers-reduced-motion`.

## القيود المتبقية

المشهد واجهة تفسيرية وليس مصدراً لبيانات تشغيلية. لا يعرض مؤشرات حية، ولا ينفذ تتبعاً لكل محطة، ولا يضيف تشفيراً أو Blockchain أو أسعاراً أو نسب نجاح. كذلك لا يغيّر منطق الصفقات أو صلاحيات الخادم أو مسارات التسجيل. أي توسعة مستقبلية لهذه العناصر يجب أن تمر عبر نماذج وواجهات وصلاحيات واختبارات مستقلة قبل عرضها للمستخدم.
