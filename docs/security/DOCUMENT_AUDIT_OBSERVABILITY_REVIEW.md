# مراجعة رفع الوثائق وسجل التدقيق والمراقبة

## مثبت حالياً

تتحقق طبقة الوثائق من نوع PDF الفعلي مقابل MIME والامتداد، وترفض أسماء المسارات التي تحتوي على traversal. كما يثبت عقد المراقبة عدم إرسال كلمات المرور أو محتوى الوثائق أو بيانات الأعمال الحساسة، مع حجب authorization وcookie وstack، وإضافة request ID للأخطاء والطلبات.

## فجوات التشغيل الإنتاجي

لم تُثبت هذه الاختبارات وحدها دورة تخزين S3 كاملة بروابط presigned قصيرة العمر، أو تحقق ملكية الوثيقة عند التنزيل، أو فحص حجم الملف ومعدل الرفع ومكافحة الملفات الخبيثة. كما لم تُثبت وجود retention policy لسجل التدقيق، أو تنبيه تشغيلي عند فشل الرفع أو تكرار محاولات الوصول.

## معيار الإغلاق

يتطلب الإغلاق اختبار تكامل لا يضع bytes حساسة في قاعدة البيانات، ويثبت أن التنزيل يمر عبر تفويض المالك وحالة الصفقة، وأن الرابط المؤقت ينتهي، وأن أحداث الرفع والتنزيل والفشل والتعديل تُسجل دون plaintext، مع مؤشرات مراقبة قابلة للتنبيه.

## إصلاح منفذ بعد المراجعة

تمت إضافة تنقية موحدة لاستجابات رفع وتنزيل وثائق المتعامل والصفقات والعروض، بحيث لا تعيد `storageKey` أو `storageUrl` الداخليين. يبقى إنشاء الرابط الموقّت محصوراً في مسار التنزيل المصرّح به، وتُسجّل عملية التنزيل في سجل التدقيق. أضيف اختبار عقدي يمنع عودة الصيغة القديمة مباشرة.

هذا الإصلاح لا يساوي تشفيراً إنتاجياً للملفات، ولا يثبت بعد سياسة احتفاظ أو تكامل S3 مستقل أو اختبار ملكية تكاملي على بيانات قاعدة فعلية.
