# مراجعة التفويض وIDOR

## مثبت بالاختبارات الحالية

تُرفض الإجراءات المحمية للزائر غير المصادق، ويُمنع المستخدم العادي من تعيين أدوار authority أو regulator لنفسه. كما تُقيد قراءة التدقيق بالـ regulator وadmin، وتُقيد بيانات بوابة المصلحة المتعاقدة بدور authority، وتُمنع صلاحيات إنشاء المناقصات أو إرسال العروض أو تقييمها أو الإسناد عن الأدوار غير المناسبة.

## ما يحتاج مراجعة إضافية قبل Pilot

الاختبارات الحالية تعتمد بدرجة كبيرة على عقود صلاحيات وأرقام معرفات ثابتة، ولا تثبت لكل إجراء حساس عزل المورد أو المصلحة المتعاقدة عن كائنات مستخدم آخر في قاعدة بيانات فعلية. يجب إضافة اختبارات تكامل تنشئ مستخدمين وكيانات منفصلة وتتحقق من رفض الوصول إلى tender وbid وdocument وopening session وnotification وsubscription request غير المملوكة.

## معيار الإغلاق

لا يُغلق بند IDOR قبل مرور مصفوفة صلاحيات لكل إجراء حساس على قاعدة بيانات اختبارية، مع حالات نجاح وفشل للمالك وغير المالك والمفوض والمنظم ومدير النظام، وتسجيل قرار التفويض في سجل التدقيق دون تسريب محتوى العرض.
