# BACK TO REGISTRATION IMPLEMENTATION PLAN

## النطاق والقرار المعماري

سيُنفّذ الزر كإجراء ثانوي موحّد داخل `DashboardLayout`، لأن هذا الغلاف المشترك يحيط بالبوابات الثلاث داخل `/app` ويملك منطقة الرأس المشتركة. بذلك يغطي الحل Supplier وAuthority وRegulator دون تكرار زر مستقل داخل كل مساحة عمل، ودون تغيير منطق الصلاحيات أو تدفق OAuth.

سيكون النص الظاهر هو **«العودة إلى صفحة التسجيل»**، وسيستخدم رابطاً داخلياً مسمّى عبر helper مشترك بدلاً من تكرار النص الحرفي للمسار في المكونات. المسار المستهدف هو `/login`، أي صفحة اختيار البوابة، وليس `startLogin()`؛ فالعودة إلى صفحة التسجيل لا ينبغي أن تبدأ OAuth أو تغيّر جلسة المستخدم تلقائياً.

## الصفحات المتأثرة

| الصفحة أو الغلاف | الحالة | القرار |
|---|---|---|
| `DashboardLayout` | غلاف مشترك للبوابات الثلاث داخل `/app` | إضافة الزر في رأس الصفحة كمكوّن ثانوي؛ يغطي Supplier وAuthority وRegulator مركزياً |
| `Portal` | نقطة التفرع حسب الدور داخل `/app` | لا تعديل مباشر متوقع؛ سيستفيد من `DashboardLayout` القائم |
| `SupplierWorkspace` | مساحة المتعامل الاقتصادي | لا إضافة محلية لتجنب التكرار؛ الزر يظهر في الغلاف المشترك |
| `AuthorityShell` / بوابة المصلحة المتعاقدة | مساحة محمية داخل الغلاف المشترك | لا إضافة محلية؛ التغطية مركزية |
| `CentralAdminPortal` / بوابة الإدارة المركزية | مساحة محمية داخل الغلاف المشترك | لا إضافة محلية؛ التغطية مركزية |
| `Login` | صفحة التسجيل نفسها | لا إضافة زر عودة إلى التسجيل؛ الصفحة تعرض بالفعل رابط العودة إلى الصفحة الرئيسية، وإضافة زر لنفس الصفحة ستكون غير منطقية |
| `Home` | صفحة الهبوط العامة | لا إضافة؛ زر «الدخول للمنصة» هو الإجراء المناسب هنا |
| `NotFound` | صفحة خطأ عامة | لا إضافة في هذه المرحلة؛ الهدف الأساسي هو البوابات الداخلية والصفحات المحمية |
| حالة `DashboardLayout` غير الموثق | بطاقة «الدخول مطلوب» | لا استبدال زر «تسجيل الدخول» الحالي؛ هذا إجراء Primary صحيح لاستعادة الدخول، وليس عودة إلى صفحة التسجيل بعد الدخول |

## مكان الزر وتصميمه

يوضع الزر في منطقة الرأس المشتركة داخل `DashboardLayout`، بجوار معلومات المستخدم وقبل قائمة الحساب أو في مجموعة إجراءات الرأس على الشاشات الصغيرة. سيكون `Button` من نمط `secondary` أو رابطاً مرئياً بنمط ثانوي، بخلفية هادئة وحدّ واضح، ولن ينافس إجراءات البوابة الأساسية.

يجب أن يملك الزر حلقة تركيز مرئية عبر `focus-visible:ring`، ونصاً واضحاً في RTL، ومساحة لمس مناسبة على الهاتف. لا يعتمد التنفيذ على أيقونة وحدها؛ ويمكن استخدام سهم اتجاهي صغير بصرياً مع بقاء النص قابلاً للقراءة.

## route الهدف وRoute Helper

| العنصر | القرار |
|---|---|
| المسار الهدف | `/login` |
| طريقة التنقل | `Link` أو `setLocation` من Wouter، دون إعادة تحميل غير لازمة |
| بدء OAuth | ممنوع عند الضغط على زر العودة؛ OAuth يبدأ فقط من أزرار «تسجيل الدخول» داخل `Login` |
| helper المقترح | إضافة ثابت أو دالة مشتركة مثل `AUTH_ROUTES.registration = "/login"` داخل `shared/login.ts` أو وحدة routes مشتركة |
| portal context | لا يُفرض سياق بوابة عند العودة؛ صفحة `/login` هي نقطة اختيار البوابة الموحدة |

سيُراجع تأثير الانتقال على session state قبل التنفيذ. إذا كان المستخدم مسجلاً، فلن يُسجّل الخروج تلقائياً؛ الزر ينقل فقط إلى صفحة التسجيل، بينما تظل آلية `Login` الحالية مسؤولة عن إعادة التوجيه إلى `/app` عند اكتشاف جلسة فعالة.

## الملفات التي ستتغير

| الملف | نوع التغيير |
|---|---|
| `shared/login.ts` أو وحدة route مشتركة مناسبة | إضافة route helper لمسار `/login` إذا لم يوجد helper مكافئ |
| `client/src/components/DashboardLayout.tsx` | إضافة الزر الثانوي في الرأس، مع رابط RTL وحالة focus |
| `server/` اختبار عقدي مناسب مثل `server/back-to-registration.view.test.ts` | التحقق من وجود النص، المسار المسمّى، وعدم استدعاء `startLogin` من زر العودة |
| `todo.md` | تسجيل التنفيذ والاختبارات بعد إتمامها |
| `back_to_registration_implementation_report.md` | توثيق الصفحات المشمولة، سبب الاستثناءات، ونتائج التحقق |

لن تُعدّل `Login.tsx` أو `Home.tsx` أو البوابات الفردية إلا إذا كشف الفحص أثناء التنفيذ عن حاجة توافقية محددة. الهدف هو إبقاء التغيير مركزياً وصغيراً.

## هل التنفيذ مركزي؟

نعم. التنفيذ المقترح **مركزي بنسبة أساسية داخل `DashboardLayout`**، مع helper مسار مشترك واختبار عقدي مستقل. هذا يغطي البوابات الفعلية الثلاث ويمنع اختلاف التسمية أو السلوك بينها. الاستثناءات المقصودة هي صفحة Login نفسها، وصفحة Home، وحالة عدم وجود جلسة داخل DashboardLayout، لأن لكل منها إجراءً مناسباً قائماً ولا تمثل عودة من بوابة داخلية إلى صفحة التسجيل.

## حدود التنفيذ

لا يشمل هذا التغيير تسجيل الخروج، ولا إعادة تشغيل OAuth، ولا تغيير أدوار المستخدم، ولا إضافة مسارات جديدة، ولا تعديل حماية الخادم. ستُختبر الاستجابة على سطح المكتب والهاتف واتجاه RTL وحالة التركيز بلوحة المفاتيح قبل اعتماد النسخة.

## حالة الخطة

هذه الوثيقة تمثل مخرج PHASE 2 التخطيطي. لم يُنفّذ أي تعديل واجهة أو كود حتى الآن. التنفيذ يبدأ فقط بعد اعتماد هذا المخطط.
