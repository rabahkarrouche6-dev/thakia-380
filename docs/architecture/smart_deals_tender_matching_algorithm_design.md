# SMART DEALS TENDER MATCHING ALGORITHM DESIGN

## 1. Executive Summary

يُنفَّذ MVP كمحرك مطابقة إرشادي deterministic داخل الخادم، وليس كنظام قبول أو رفض قانوني، ولا كتنبؤ باحتمال الفوز. يقرأ فقط الصفقات المنشورة المتاحة للمورد وحقول الملف المؤسسي الموجودة فعلياً في المخطط الحالي، ثم يطبق بوابة أهلية صريحة للصفقة المنشورة وغير المنتهية، ويحسب درجة قابلة للتفسير من أربعة عوامل متاحة: الفئة، التشابه النصي، الموقع، وجاهزية الملف.

البيانات غير الموجودة حالياً، مثل الشهادات والخبرات والقدرة التشغيلية وحجم المؤسسة والكلمات المفتاحية ومتطلبات الأهلية، لا تُستنتج ولا تُستخدم كبيانات وهمية. عند غيابها، يُخفض وزن العامل المتاح أو يُسجل كفجوة بيانات، ولا يُقصى المورد الجديد بسبب غياب التاريخ السابق.

## 2. Recommended MVP Algorithm

يتكون التنفيذ الحالي من أربع طبقات مفاهيمية:

1. **Eligibility Gate:** الصفقة مؤهلة إرشادياً فقط إذا كانت `status = published` وموعدها المستقبلي وفق وقت الخادم. الصفقة المغلقة أو المنتهية تُرجع `Not Eligible` ودرجة صفر.
2. **Structured Scoring:** أوزان MVP الحالية: الفئة 45%، التشابه النصي 35%، الموقع 10%، جاهزية الملف 10%. عند غياب عامل، يُعاد تطبيع الأوزان المتاحة مع حد أدنى 45% حتى لا يهيمن عامل واحد غير جوهري.
3. **Semantic Matching:** تطبيع النص العربي وإزالة التشكيل وتوحيد بعض الحروف، مع قاموس مرادفات عربي/فرنسي/إنجليزي محدود للفئات المتاحة. لا توجد embeddings أو TF-IDF في MVP.
4. **Explanation Layer:** الأسباب والفجوات والإجراء المقترح تُعاد في عقد منظم. اللغة إرشادية: «راجع التفاصيل» و«أكمل بيانات مؤسستك»، ولا تدعي الأهلية القانونية أو ضمان الفوز.

## 3. Data Model Needed

لا تحتاج النسخة الحالية إلى migration. تعتمد على `Profile.organizationName`, `Profile.address`, `Profile.completion` وحقول `Tender.title`, `description`, `category`, `location`, `deadline`, `status`, `reference`, `id`. تُقرأ الصفقات عبر `listPublishedTenders` والملف عبر `getProfile` داخل إجراء خادمي محمي بدور المورد.

حقول V1 المقترحة، ولا تُنفذ في هذه المرحلة، تشمل `businessActivity`, `subActivities`, `serviceRegions`, `employeeCount`, `capacityTags`, `certifications`, `certificationExpiry`, `experienceCategories`, وحقولاً منظمة لمتطلبات الصفقة. يجب أن تسبقها مراجعة قانونية وتصميم schema مستقل.

## 4. Eligibility Rules

| القاعدة | MVP | السلوك |
|---|---:|---|
| حالة الصفقة منشورة | نعم | غير المنشورة `Not Eligible` |
| الموعد النهائي مستقبلي | نعم | المنتهية `Not Eligible` |
| تطابق نشاط مانع | لا | لا توجد بيانات موثوقة تسمح بقاعدة إقصاء |
| النطاق الجغرافي الإلزامي | لا | الموقع عامل ترجيح فقط |
| الشهادات والوثائق | لا | غير متاحة كبيانات مطابقة |
| الحجم والقدرة | لا | لا تُفترض من الميزانية |
| نوع الكيان | لا | خارج schema الحالي |

بالتالي، **Eligibility Status في MVP تشغيلي/زمني** وليس شهادة أهلية قانونية أو مهنية.

## 5. Feature Table with Weights

| العامل | الحقول الفعلية | الوزن | عند الغياب |
|---|---|---:|---|
| Category Match | اسم المؤسسة وفئة الصفقة | 45% | درجة محايدة مع فجوة بيانات |
| Semantic Match | اسم المؤسسة مقابل عنوان/وصف/فئة الصفقة | 35% | درجة محايدة إذا غاب اسم المؤسسة |
| Geo Match | عنوان المؤسسة وموقع الصفقة | 10% | درجة محايدة |
| Readiness | نسبة اكتمال الملف | 10% | صفر/فجوة جاهزية |
| الخبرة | غير متاحة | 0% | لا تؤثر |
| الوثائق والشهادات | غير متاحة | 0% | لا تؤثر |
| القدرة والحجم | غير متاحة | 0% | لا تؤثر |
| الأداء السابق | غير متاح | 0% | لا يؤثر ولا يعاقب المورد الجديد |

## 6. Scoring Formula

لصفقة منشورة وغير منتهية:

`score = 100 × (0.45×category + 0.35×semantic + 0.10×geo + 0.10×readiness) / max(0.45, availableWeight)`

يُحصر الناتج بين 0 و100. التصنيف الحالي: `Highly Relevant` من 80، `Relevant` من 60، `Potential Fit` من 40، وما دون ذلك `Low Fit`. الصفقة غير المؤهلة تشغيلياً تحصل على `Not Eligible` ودرجة صفر.

## 7. Explanation & Gap Logic

تُعرض حتى ثلاثة أسباب ذات درجة محايدة أو موجبة، وحتى فجوتين من العوامل الضعيفة أو غير المتاحة. أمثلة: «يوجد توافق مباشر أو اصطلاحي مع فئة الصفقة»، «لا تتوفر بيانات موقع كافية للمقارنة»، و«أكمل الملف المؤسسي لتحسين دقة المطابقة». الإجراء: مراجعة الصفقة والوثائق المنشورة وإكمال الملف قبل اتخاذ قرار التقديم.

زر «مراجعة التفاصيل» ينقل إلى قائمة الصفقات المنشورة الحالية. لا تستنتج الواجهة تفاصيل غير موجودة ولا تُظهر التوصية كقرار أهلية.

## 8. Suggested DB Fields

لا تُضاف حقول في MVP. في V1، تُضاف الحقول بعد إثبات الاستخدام وبموافقة domain/legal: نشاط منظم، مناطق الخدمة، القدرات، الخبرة، الشهادات وتواريخها، ومتطلبات الصفقة الصريحة. يجب حفظ مصدر كل قيمة وتاريخ تحديثها وعدم تخزين نسخ غير لازمة من الوثائق داخل سجل المطابقة.

## 9. Services / Modules

التنفيذ الحالي: `server/tenderMatching.ts` لخوارزمية pure قابلة للاختبار، و`server/routers.ts` لإجراء `tenders.recommended` المحمي بدور `supplier`. لا توجد خدمة خلفية مستقلة أو مهمة دورية أو نموذج ML.

## 10. API Design

`protected supplier procedure: tenders.recommended` يعيد حتى خمس نتائج مرتبة، من مصدر الصفقات المنشورة والملف الحالي. لا يستقبل مدخلات من العميل، ما يمنع التلاعب بالملف أو تمرير معرفات خارجية. لا يُعاد أي token أو وثيقة أو بيانات مورد آخر.

## 11. UI Integration

أضيف قسم «الصفقات الأنسب لك» إلى الصفحة الرئيسية لمساحة المورد، مع حالات loading وerror وempty، العنوان والمرجع والدرجة والتصنيف وسببين مختصرين وزر مراجعة. يظهر تنبيه واضح بأن الترتيب إرشادي ولا يمثل قرار أهلية أو ضماناً لقبول العرض. يعمل القسم داخل RTL وعلى شبكة هاتفية متجاوبة.

## 12. Evaluation Metrics

في MVP تُقاس مؤشرات تشغيلية فقط: زمن الاستجابة، نسبة نجاح الإجراء، نسبة ظهور توصيات، نسبة النقر إلى قائمة الصفقات، ونسبة إكمال العرض بعد النقر. لا تُقاس «دقة الفوز» أو جودة المورد لأن البيانات التاريخية غير متاحة ولا يجوز ادعاؤها.

## 13. Risks / Bias Controls

الخطر الرئيسي هو أن اسم المؤسسة ليس بديلاً موثوقاً عن النشاط التجاري. لذلك تُعرض النتيجة كتوصية فقط، ولا توجد قاعدة إقصاء بسبب غياب التاريخ أو الحجم أو الوثائق غير المتاحة. لا تُستخدم بيانات حساسة، ولا تُرسل وثائق أو كلمات مرور أو بيانات منافسين، ولا يُسمح للمحرك بتغيير حالة الصفقة أو العرض.

## 14. Phased Rollout

| المرحلة | النطاق |
|---|---|
| MVP | المطابقة الحالية الحتمية، أربعة عوامل فعلية، قسم المورد، اختبارات الخصوصية والحالات |
| V1 | حقول نشاط ومناطق وقدرات وشهادات منظمة، eligibility rules صريحة قابلة للتدقيق، وتحسين CTA إلى تفاصيل صفقة محددة |
| V2 | قاموس مجال مُدار، TF-IDF أو embeddings قابلة للتفسير، تقييم offline، ومراقبة الانحياز؛ دون قرارات تلقائية |

## 15. Implementation Boundary

النسخة الحالية لا تنفذ خبرة أو وثائق أو قدرة أو نوع كيان أو شروط أهلية لأنها غير ممثلة في قاعدة البيانات الحالية. لا تُستخدم النتيجة في التقييم أو الإرساء، ولا تصل إلى المصلحة المتعاقدة أو الإدارة المركزية، ولا تستبدل فحص الصفقة الرسمي أو الوثائق المنشورة.
